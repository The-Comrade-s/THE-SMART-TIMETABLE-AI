# Audit and Completion Report

Status: **READY WITH MINOR LIMITATIONS.** Everything listed under "Verified" was measured by running it in the build environment. The main item not verified is how the interface looks in a real browser (see Limitations 1).

## 1. Audit summary (before and during final testing)
Reviewed: architecture, 18 models and the migration, authentication, permissions, every management module, the Genetic Algorithm, generation workflow, conflict detection, lifecycle, visualisation, exports, scripts and documentation.

Defects found by the audit or by the tests, and fixed:
1. The initial migration (autogenerated against SQLite) used `DEFAULT 1` for boolean columns, which PostgreSQL rejects. Replaced with a portable boolean default; verified on PostgreSQL 16 (upgrade, downgrade, upgrade, and `alembic check` reports no drift).
2. The generation page raised `KeyError` when no re-optimisation parent was selected (found by the UI test). Fixed.
3. Duplicate-record errors were not a subclass of the validation error, so callers that handle validation errors missed them. Fixed.
4. Several of my first draft tests contained non-assertions (`or True`) and one empty stub. Rewritten to make real assertions (including a lab course placed in a normal room, and an invalid timetable never ranked above a valid one).
5. Security scan (bandit): `assert` used for runtime checks in the connection module replaced with explicit errors; the application name on the login page is now HTML-escaped. Remaining bandit notes are low severity and accepted: `random` is used for the optimiser and demo data (not security), and `xml.sax.saxutils.escape` is used to escape text for PDF paragraphs, not to parse XML.
6. Demonstration data initially produced unplaceable sessions (lab capacity below group size); the seed now produces feasible data.

Unused files removed: the foundation-stage placeholder sample data and "pending page" view. The Pandas dependency from the original brief was removed because nothing uses it.

## 3. Security improvements implemented
Argon2id password hashing; generic login errors; lockout for 15 minutes after 5 failed attempts; server-side sessions stored as hashes with 8-hour expiry and revocation on logout or deactivation (re-checked on every page run); central permission checks inside every service function; no public registration; first-admin creation only through a command-line script and only while no super admin exists; the last active super admin cannot be demoted or deactivated; search terms are escaped and all queries go through SQLAlchemy; user-supplied text is HTML-escaped in custom components; viewers can only see and export published timetables (enforced in the service layer, with a test); error messages shown to users never include exception text from the database or algorithm.

## 4. Deployment readiness
`requirements.txt`, `.env.example`, migrations, health scripts, logging to stdout and deployment steps are present. The Dockerfile has not been built.

## 5. Known limitations and outstanding items
1. **Visual quality was not verified in a browser.** The sandbox had no browser. Dark and light styling, the bold uppercase sidebar and the active-item highlight, the timetable grid layout, responsiveness on tablet and phone, and the print button were checked only through computed contrast ratios, test of the generated CSS text, and rendering without errors. The sidebar styling relies on Streamlit's button test ids, which may change in other Streamlit versions. Please look at both themes on desktop and a phone-width window before the demonstration.
2. Sign-in persists for the browser session (server-side session plus Streamlit session state); a full page refresh or a new tab requires signing in again.
3. Admin permissions are global; there is no per-department scoping of "assigned" records.
4. Generation runs in a background thread inside the Streamlit process: use one instance; a restart interrupts a running job. A stopped or interrupted run is saved as a timetable with its real validation result.
5. The pairwise independent validator was measured only up to 151 sessions; very large datasets (thousands of sessions) are untested.
6. Academic levels are the numbers 100 to 600; ND/HND-style levels are not modelled separately. Assignments require the course level and semester to match the student group.
7. Excel exports use combined worksheets with filters (department, lecturer, classroom, student group) rather than one worksheet per entity.
8. The browser print button (`window.print`) and the print stylesheet were not tested in a real browser; the PDF export is the dependable print route.
9. `st.dialog` confirmation dialogs were not exercised by automated tests (the underlying service actions are tested).
10. Remaining uncovered code is mostly UI branches (for example edit forms and the student-group page) and CLI prompts.
11. Demonstration datasets are synthetic and mostly feasible; behaviour on tight real data is unknown. The application reports unresolved violations rather than hiding them.

## 6. Recommendations
Run the application against a copy of real data in a real browser; add a Streamlit-version pin once the visual check is done; add browser-based end-to-end tests; add a password-reset flow and per-department admin scoping if required.

## Defect found and fixed during this stage
Synthetic lecture generation initially used every active room, including the institution's own rooms. Generation can now be restricted to a set of rooms (`room_ids`), and synthetic generation uses only the synthetic rooms (tested).

## Limitations specific to this stage
1. Ten titles are flagged because another title in the document continues the same text mid-word (the source clips some titles). Clipped titles with no such counterpart cannot be detected and are not flagged.
2. Faculty grouping is only known for the two day ranges in the PDF legend (days 1 to 8 and 9 to 16); the PDF does not give a faculty per course.
3. The PDF has no examination durations. Conflict detection is slot based unless a duration is assumed. The student groups are synthetic, so the two overlaps found describe the synthetic grouping only.
4. Which course codes count as computing courses is inferred from the code prefix (CIT, COS, CSC, CYB, IFT, INS, CSO). NOUN-prefixed and Batch entries are not used for the synthetic lecture data.
5. The extractor is tailored to this document's table layout. A differently laid out PDF is reported as INVALID or NEEDS_REVIEW; it is not guaranteed to extract correctly.
6. The DATASETS screens were exercised with Streamlit's test harness only; as before, nothing was inspected in a real browser (see Limitation 1 above). The confirmation dialogs were not clicked by automated tests (the underlying import and removal services are tested).
7. The `st.file_uploader` path (uploading a PDF) was not exercised by automated tests; the bundled-file path was.
